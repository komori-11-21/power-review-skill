# `scripts/stage1_db/slots/screen_on/`：亮屏活跃分支查询槽位

## 主要实现什么
对应 [screen_on_rules.md](../../../../references/screen_on_rules.md)，在真实 `.db` 中提取亮屏异常段与 `Ref` 段的 8 个排查维度数据：

1. **槽位 1（L1 必选）**：亮屏全硬件器件（Display/CPU/GPU/DSS/DDR/ROM/WiFi/BT/Audio/Camera 等）模拟占比 `Share %` 与亮屏模拟覆盖率；
2. **槽位 2（L2 硬证据）**：屏幕平均亮度、LTPO 各刷新率档位（`1Hz~144Hz`）真实驻留比及 `>=120Hz` 高刷比、`GPU / DSS` 合成耗电比；
3. **槽位 3（L2 归因）**：各应用前台驻留比、前台模拟占比 `Share %`，以及基于“时间区间重叠 / 窗口状态标记 / 前台时长总和 `> 1.2Δt`”的 **`[平板分屏/多窗并发模式]`** 自动打标（防止先后切换使用误判成分屏）；
4. **槽位 4（L2 核心归因）**：全机亮屏后台耗电总占比（供识别 `>25%` 异常陪跑，含缺前后台区分字段时的 `前台时长=0` 回退公式）与后台持锁占比；
5. **槽位 5（L3 算力）**：应用内部 `Thread_*` 真实 CPU 时长占比与 CPU 大小核高频点驻留比（缺线程表附 `hiperf` 补抓提示）；
6. **槽位 6（L3 图形访存）**：GPU 频点活跃率/高频卡死占比，以及 DDR 内存 / ROM 闪存消耗应用 `Share %`；
7. **槽位 7（L3 通信媒体外设）**：网络速率（`MB/h`）与包率（`包/h`）、前后摄 Camera 与 Audio 开启占比、亮屏手写笔高频采样/无线充及键盘占比；
8. **槽位 8（L3 温升堆栈）**：平均/最高壳温、热降频（`ThermalLevel`）时长占比与端侧 3 分钟异常事件/调用栈。
