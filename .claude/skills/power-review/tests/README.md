# `tests/`：自动验收与防改坏回归体系说明

本目录用于保障后续在真实环境编写和迭代 `scripts/` 时**口径不算偏、缺表不崩溃、改旧规则不弄坏老场景**。当前先保留目录与验收说明，待回内网见到真实 `.db` 和日志样本后再填充脱敏夹具与测试脚本。

## 目录结构

| 子目录 | 主要用途 | 依赖真数据情况 |
| :--- | :--- | :--- |
| `fixtures/` | 存放从真实问题单裁剪脱敏后的微缩 `.db` 与日志片段 | 需回内网采样脱敏后放入 |
| `unit/` | 单独验证切片过滤、双榜合并、探表降级、知识库召回、日志时间对齐 | 纯算法模块不依赖；SQL 与日志解析需对照真实格式后补 |
| `integration/` | 模拟一次端到端全链路调用（阶段一二出证据包 + 阶段三查日志 CLI） | 需搭配 `fixtures/` 中脱敏样本启用 |

## 建议必测的 5 类核心场景
1. **灭屏常规漏电场景**：包含充电期与拔充 5 分钟回落期干扰，存在高耗电 `Target` 与正常 `Ref` 切片；
2. **未解释耗电 / 软件盲区场景**：高耗电但软件模拟覆盖率极低（如 `< 35%`），需能先自检是不是缺表或算漏，确认没算漏后再识别为外设/底电流盲区；
3. **亮屏多窗 + 后台陪跑场景**：多应用前台并发打标 `[平板分屏/多窗并发模式]` + 后台陪跑超过红线；
4. **整库持续漏电与单段场景**：验证 `Ref` 也高或全库仅 1 段（`Ref = 无`）时 4 列表仍正常输出第 ① 列实测霸榜项；
5. **缺表自动降级 + 专有新表扩展场景**：故意删掉外设/线程/堆栈表，验证自动输出跳过提示与线下 `hiperf` 补抓建议，不报错中断。
