# `tests/unit/`：各环节单元测试规划

## 主要实现什么
把流水线拆成独立小单元验证，专门抓肉眼看报告最容易漏掉的边缘计算错误。

## 计划覆盖的测试点

### 一、纯逻辑与配置校验（不依赖真实 `.db`/日志）
1. **配置加载**：验证 [thresholds.json](../../assets/config/thresholds.json) 键值完整无语法错误；
2. **切片过滤算法**：验证充电态与拔充回落期准确剔除、短于最小时长的碎片正确丢弃（默认值见 `thresholds.json`）、仅剩 `level %` 时正确回退计算；
3. **双榜合并算法**：验证排名第 7 但对比突增进 Top3 的小比例对象能通过 `[突增入选]` 进表，其余长尾准确折叠为 `Others`；验证 `Ref = None` 时不报错；
4. **知识库召回**：验证包名/锁名精确匹配命中，且未知新包名触发某维度时能召回同类旧案例卡片；
5. **只读探表与跳过提示**：验证 `sqlite_master` 识别任意表结构、缺表返回标准跳过说明且不抛 SQL 异常。

### 二、对接真实结构后补全的测试点
6. **各维度 SQL 适配器**：基于脱敏 `.db` 验证累加器 `MAX-MIN` 减法不错、跨边界起止持锁时间能按切片截断、异常时不会溢出整份切片时长；
7. **日志行解析与 4 大工具**：验证真实 `hilog` 年份/跨午夜补全、`kernel_log` 时钟转换、包名重启多 `PID` 聚合、差分 `>5x` 筛选和前后 35 行流式读取准确率。
