# 《具体问题知识库》

> **定位**：存放一题一卡的历史实战问题，用于两类场景：
> 1. **老问题秒杀**：当 `.db` 中的包名、锁名、IRQ 或关键字与某张卡片完全命中时，直接按卡片核实日志并输出结论；
> 2. **未知新问题“照猫画虎”**：当出现没见过的新模块时，根据异常维度抽取同类别旧卡片，把卡片中“① DUBAI 怎么看 $\rightarrow$ ② 日志怎么看”的排查动作迁移到新嫌犯身上。

> **免重构约定**：你可以直接将已有的历史问题笔记粘贴到本文档下方（即使格式不完全一致也可以先直接贴入；需要批量规范化时再整理为下方的 3 段式卡片）。

## 示例卡片（初版示范模板，实测后可保留或替换）

## 案例示例 1：某模块持锁未释放导致灭屏无法深睡 `[示范模板]`
- **【现象类别】**：灭屏待机 / 持锁异常 (`SQL_OFF_2` / `RunningLock` / `Wakelock`)
- **【关键词/模块】**：`SyncWake`、`com.xxx.cloud`、`AcquireRunningLock`、`ReleaseRunningLock`
- **① DUBAI (.db) 怎么看**：
  灭屏段 AP 深睡率低（如 `<80%`），在【持锁表】看到某应用或系统服务的锁（如 `SyncWake` / `AudioMix`）实测占比或对比突增排名居前，且在灭屏应用/线程表常伴随同一包名共振。
- **② 日志怎么看**：
  在异常时间窗内搜索该锁名或持锁申请关键字，核对是否存在“有申请（Acquire）无释放（Release）”；同时展开该进程 `PID` 上下文，检查是否卡在网络同步超时或死循环重试未走到释放路径。
- **③ 结论与转交团队**：
  确认为持锁泄露 -> 转交对应业务团队（如云同步转【云服务组】，音频锁转【多媒体音频组】）。

## 案例示例 2：手写笔吸附状态震荡导致灭屏反复无线复充漏电 `[示范模板]`
- **【现象类别】**：灭屏待机 / 外设盲区漏电 (`SQL_OFF_1` / `SQL_OFF_6` / `模拟覆盖率低`)
- **【关键词/模块】**：`stylus`、`wireless_charge`、`hall_stylus_irq`、`hall`
- **① DUBAI (.db) 怎么看**：
  灭屏电池真实均流明显偏高（如 `>35mA`），但所有已知软件器件加起来的【软件模拟覆盖率极低（`<35%`）】，或在平板外设表 / 硬件中断表里看到手写笔在位/霍尔唤醒中断（如 `hall_stylus_irq`）频次异常。
- **② 日志怎么看**：
  在日志中搜索 `stylus` / `wireless_charge` / `hall` 等关键字，查看是否存在 `charge start <-> charge stop` 或电量 `99% <-> 100%` 的周期性反复横跳打印。
- **③ 结论与转交团队**：
  确认为手写笔无线复充状态机震荡 -> 转交 **【平板外设与硬件驱动组】**。
