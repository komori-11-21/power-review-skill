# 亮屏审单查表规范（`Skill_亮屏审单` 分支通用规则）

> **使用说明（初版待真机校准）**：当分析切片为**纯亮屏活跃状态**时读取本文档。下文中的阈值与 8 维拆解均为初版框架，**若示例数值与 `../assets/config/thresholds.json` 不一致，一律以 `thresholds.json` 为准**；回内网后按实测表结构与案例持续增删校准。

---

## 一、切片口径与异常切片入选条件

1. **有效亮屏切片口径**：过滤充电态及拔充电器后电压回落期（默认参考 `5 分钟 / 300s`），按屏幕状态连续性切出**连续纯亮屏切片**（默认参考最小时长 `>= 10 分钟 / 600s`）。
2. **收入待审 `Target_List` 条件**（满足任意一条即逐段独立分析，全库未触发时兜底取掉电最高 1 段）：
   - 切片时间窗命中 `context_ext` 用户报障时间窗；
   - 电池真实掉电率 $> 12\%/\text{h}$（或真实均流 $I_{\text{real}} > 1000\text{ mA}$）；
   - 全机亮屏**后台模拟耗电总占比 `> 25%`**。
3. **参照段 `Ref` 配对**：取同库中亮屏 $I_{\text{real}}$ 最低的一段作为 `Ref`；若全库仅有 1 段有效亮屏切片，则 `Ref = 无`。

---

## 二、亮屏 8 维逐级排查路径（L1 $\rightarrow$ L2 $\rightarrow$ L3）

### L1：定硬件大件分布与覆盖率（必看）
- **核心关注维度（`SQL_ON_1`：全硬件器件亮屏分布）**：
  - 输出 `Display / CPU / GPU / DSS / DDR / ROM / WiFi / BT / Audio / Camera / Sensor / Modem` 各自模拟能量 `Share %`（按实测降序）；
  - 计算亮屏软件模拟覆盖率，判断是否存在亮屏下未建模外设耗电（如拓展坞、大电流外接设备、笔亮屏无线充等）。

### L2：区分显示高刷、前台多窗并发与后台陪跑
1. **屏幕亮度、LTPO 刷新率档位与合成链路（`SQL_ON_2`）**：
   - **平均亮度**：核对是否属用户户外超高亮度（如 `> 80%）`正常消耗；
   - **LTPO 刷新率真实驻留比**：统计 `1Hz ~ 144Hz/180Hz` 各档占比并汇总 `>= 120Hz` 高刷总驻留比，识别静态阅读/低帧视频是否锁死高刷未降频；
   - **合成退化比值**：计算 `GPU 模拟能量 / DSS 模拟能量`，识别多窗或动效场景下硬件显示合成（DSS）是否退化为 GPU 渲染。
2. **前台场景识别与平板多窗并发判定（`SQL_ON_3`）**：
   - 计算各应用前台驻留比 `(foreground_duration / Δt) × 100%` 与前台能量 `Share %`；
   - **平板分屏/多窗并发判定**：只有满足以下并发证据之一时，才打标为 **`[平板分屏/多窗并发模式]`**：① 有 `>= 2` 个应用的前台时间区间确实重叠，或日志/表中有分屏/多窗窗口状态标记；② 全部应用前台时长总和明显超过切片时长（如 `> 1.2 × Δt`，说明肯定有同时在前台跑的应用）。*防误判提醒*：不能只看两个应用各自前台占比都 `> 30%` 就当成分屏（先后切换使用 A 和 B 也会出现各自 `> 30%`）。
3. **亮屏“后台陪跑（寄生耗电）”核心归因（`SQL_ON_4`）**：
   - 计算全机后台模拟耗电总占比 $= \frac{\text{SUM(所有应用后台能量)}}{\text{SUM(所有应用前后台总能量)}} \times 100\%$；
   - **缺字段回退公式**：若真实应用表不区分 `foreground_energy` 与 `background_energy`（仅有总能量 `total_energy`），则联合前台时长字段——凡时间窗内 `前台时长 = 0`（或极微）仍有能量消耗的应用，一律归入亮屏后台陪跑！
   - 只要后台总占比 `> 25%`（或豁免审核时发现无关后台 `>= 15%`），必抓头号后台陪跑应用（常见：图库 AI 聚类、云同步、后台编译）及后台持锁时长占比。

### L3：算力热点、图形访存、多媒体外设与热降频
1. **CPU 热点线程与大小核频点（`SQL_ON_5`）**：
   - 列出 `Thread_*` 真实 CPU 时间占比 `(thread_time秒 / Δt) × 100%`（按 `>= 2% [保底前5] ∪ 突增 Top3`）及大核高频点驻留比；
   - *无线程明细表兜底*：锁定高耗电应用 `BundleName` 后，在报告末尾自动加注线下 `hiperf` 补抓该进程热点线程栈的提示。
2. **GPU 频点与 DDR / ROM 吞吐（`SQL_ON_6`）**：
   - 算 GPU 各频点活跃率与高频卡死占比，及 DDR 内存 / ROM 闪存应用 `Share %`（多窗/大文件卡顿时重点查）。
3. **通信、音视频与亮屏外设（`SQL_ON_7`）**：
   - 核查网络速率（`MB/h`）与收发包率（`包/h`）（识别小包高频 Tail Power 拖尾）；
   - 核查前后摄 `Camera` 与外放 `Audio` 开启占比（区分正常网课会议 vs 后台偷开）；
   - 核查亮屏期间手写笔 120Hz 高频采样/无线充、磁吸键盘供电占比。
4. **机身温升热降频与端侧堆栈（`SQL_ON_8`）**：
   - 提取平均/最高壳温（`℃`）与 `ThermalLevel >= 阈值` 的热降频时长占比（`%`）；
   - 若 `.db` 在该时间窗内捕获到 3 分钟高负载 `AbnormalEvents` 或 `Stacktrace`，直接摘录作硬证据。

## 三、亮屏判定提醒
- 亮屏高耗电不一定都是 Bug！先查 [general_guide.md](./general_guide.md) 确认是否属于有前提的正常重度使用；
- 若属于正常前台重度游戏/多窗但**同时存在严重无关后台陪跑（`>= 15%`）、长持锁或异常高频唤醒**，应明确指出“前台使用合理，但存在异常后台或持锁/唤醒问题需继续排查”。
