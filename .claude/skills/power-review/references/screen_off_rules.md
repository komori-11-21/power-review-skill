# 灭屏审单查表规范（`Skill_灭屏审单` 分支通用规则）

> **使用说明（初版待真机校准）**：当分析切片为**纯灭屏待机状态**时读取本文档。下文中的阈值与 7 维拆解均为初版框架，**若示例数值与 `../assets/config/thresholds.json` 不一致，一律以 `thresholds.json` 为准**；回内网后缺哪维就删/跳过哪维，有专有硬件/新指标直接增补到本文档。

---

## 一、切片口径与异常切片入选条件

1. **有效灭屏切片口径**：过滤充电态及拔充电器后电压回落期（默认参考 `5 分钟 / 300s`），按屏幕状态连续性切出**连续纯灭屏切片**（默认参考最小时长 `>= 30 分钟 / 1800s`）。
2. **收入待审 `Target_List` 条件**（满足任意一条即逐段独立分析，全库未触发时兜底取掉电最高 1 段）：
   - 电池真实均流 $I_{\text{real}} > 20\text{ mA}$（或真实掉电率 $> 0.3\%/\text{h}$）；
   - AP 深睡率 `< 80%`；
   - 切片时间窗命中 `context_ext` 中的用户报障时间段。
3. **参照段 `Ref` 配对**：取同库中灭屏 $I_{\text{real}}$ 最低的一段作为 `Ref`；若全库仅有 1 段有效灭屏切片，则 `Ref = 无`。

## 二、灭屏 7 维逐级排查路径（L1 $\rightarrow$ L2 $\rightarrow$ L3）

### L1：定休眠质量、划软硬边界（必看）
- **核心关注维度（`SQL_OFF_1`：AP 休眠与软件模拟覆盖率）**：
  1. **AP 深睡率 (`%`)** $= (\text{AP 深睡秒数} / \Delta t) \times 100\%$ 与各 **子系统休眠率 (`%`)**（AOC 传感器中枢 / Wi-Fi / BT / Modem）。
  2. **软件模拟覆盖率 (`%`)** $= (\text{SUM(全硬件器件模拟能量 mAs)} / \Delta t) / I_{\text{real}} \times 100\%$（先统一换算成 `mAs`，防 `mAh`/`uAh` 差 3600 倍且不重复汇总父子项）。
- **分支分流判断**：
  - **高深睡 + 覆盖率 `< 35%`（初版参考）**：先核查是否存在缺硬件器件表、采样时间不全或单位漏换算为 `mAs`；确认没算漏后依然偏低，说明存在**未解释耗电** $\rightarrow$ 重点怀疑软件监控盲区（外设漏电 / 硬件底电流漏电），核查外设状态与外设中断，必要时提示线下实测；
  - **低深睡（`< 80%`）或高覆盖率**：软件层确实一直在活动 $\rightarrow$ 进入 L2 抓持锁、唤醒和大户。
- **缺表兜底**：无子系统表时仅看 AP 深睡率；无深睡表时保留 `电池真实均流 vs 软件模拟覆盖率`。

### L2：抓持锁、追唤醒、看软硬件大户
1. **后台持锁与冻结（`SQL_OFF_2`）**：
   - 计算单锁真实时长占比 `(持锁累计秒数 / Δt) × 100%`，按 `>= 3% [保底前5] ∪ 突增 Top3 + Others` 展示；
   - 重点区分自研/三方应用锁 vs 系统代理锁，并核查后台冻结（Freeze）失败次数；若某锁霸榜且长期未释放，按“有借无还 / 代理阻塞”查日志。
2. **内核硬件中断与定时器唤醒（`SQL_OFF_3`）**：
   - 当无人长持锁但深睡依然低（睡一下醒一下）时重点查看；
   - 算硬件 `Wakeup IRQ` 频次（`唤醒次数 / 小时`）与应用 `Alarm / Timer` 触发频次（`>= 3次/h [保底前5] ∪ 突增 Top3 + Others`）。
3. **灭屏全硬件器件与后台应用模拟占比（`SQL_OFF_4`）**：
   - 分别输出各硬件器件（CPU / WiFi / BT / Audio / Sensor / Location / Modem / ROM）与各后台应用的内部 `Share %`；
   - 注意核对是否存在“熄屏听歌”（Audio 高 + 音乐类应用居首） vs 伪装无声音频保活。

### L3：线程、无线扫描、平板外设与端侧直通车
1. **灭屏偷跑 CPU 线程与无线/定位扫描（`SQL_OFF_5`）**：
   - 按 `>= 2% [保底前5] ∪ 突增 Top3` 列出 `Thread_*` 真实 CPU 时长占比 `(thread_time秒 / Δt) × 100%`；
   - 统计灭屏网络收发包率（`包/h`）、Wi-Fi Scan / BLE Scan / GPS 定位频次与时长；
   - *无线程明细表兜底*：锁定异常进程 `BundleName` 后，在报告末附线下 `hiperf` 补抓热点线程栈指令。
2. **平板专属灭屏外设状态（`SQL_OFF_6`）**：
   - 排查 **手写笔** 在位时长、无线充开启占比与充断切换频次（警惕 `100% <-> 99%` 复充死循环）；
   - 排查 **磁吸键盘** PogoPin 连接与供电时长、**皮套霍尔传感器** 误触发频次、**Type-C OTG** 外设反向供电状态；
   - *无独立外设表兜底*：若已核对未漏表、未算错单位但 L1 覆盖率仍 `< 35%`，结合 L2 `hall/otg IRQ` 标记为疑似外设盲区并建议排查外设/实测。
3. **端侧异常事件与调用栈直通车（`SQL_OFF_7`）**：
   - 若 `.db` 自带 `AbnormalEvents` 或端侧混合调用栈表，直接按异常时间窗捞取告警事件与栈文本作一锤定音证据。

## 三、灭屏常见特殊情况处理
- **正常豁免优先**：务必先核对 [general_guide.md](./general_guide.md) 中的灭屏豁免项（真大流量下载、听歌、单次正常笔充）。
- **整库全程漏电（`Ref` 同样 `> 20 mA`）**：说明正常参照段本身也在漏电，不要被第 ③ 列 `Diff ≈ 0` 迷惑，直接按第 ① 列实测霸榜 + 跨表同名共振抓常驻死循环。
